# 26-SAP-D-MSR — نسخه نمایشی (Demo Build)

این پوشه یک نسخه‌ی کامل و مستقل از یک داشبورد BI (هوش تجاری) واقعی است که تحت نام
مستقل **«26-SAP-D-MSR»** به‌عنوان **نمونه‌کار پورتفولیو** بازسازی شده — همان کد و
همان طراحی فرانت‌اند/بک‌اند پروژه‌ی اصلی، اما با **هویت برند و داده‌ی ۱۰۰٪ ساختگی**
به‌جای نام و اطلاعات واقعی شرکت مشتری. هیچ عدد، نام مشتری، نام پرسنل یا نام
بازاریابی در این نسخه واقعی نیست — همه چیز با اسکریپت `fake-data/generate.py`
تولید شده.

نام و برند شرکت/محصول اصلی به‌طور کامل با هویت مستقل «26-SAP-D-MSR» (نمایش‌داده‌شده
به‌صورت «SAP» در عنوان صفحه، ورود و نوار کناری) جایگزین شده تا این کپی به‌صورت یک
محصول پورتفولیوی مجزا و غیرقابل ردیابی به کارفرمای واقعی قابل ارائه باشد؛ فقط
ساختار و منطق کد (کامپوننت‌ها، مسیرها، الگوی UI) از پروژه‌ی اصلی به ارث رسیده. یک
نوار کوچک در بالای هر صفحه («نسخه نمایشی — تمام داده‌های این صفحه کاملاً فرضی
هستند...») هم برای یادآوری همین نکته به بازدیدکننده اضافه شده
(`frontend/src/components/layout/DemoBanner.tsx`).

## ساختار این پوشه

```
26-SAP-D-MSR/
  backend/       بک‌اند (کپی از backend/src + package.json + tsconfig.json)
  frontend/      فرانت‌اند (کپی از frontend/src + public + کانفیگ‌ها)
  fake-data/
    generate.py    اسکریپت پایتونی تولید داده‌ی ساختگی (قابل اجرای مجدد)
    output/        فایل‌های دیتابیس SQLite ساختگی (خروجی generate.py)
  README.md       همین فایل
```

## اجرای لوکال

نیازمندی‌ها: Node.js (نسخه‌ی هم‌خانواده با پروژه‌ی اصلی) و npm.

### روش سریع

فایل `26-SAP-D-MSR\start-demo.bat` را دابل‌کلیک کنید (یا از خط فرمان اجرا کنید). این
فایل اگر لازم باشد `npm install` را خودش برای بک‌اند و فرانت‌اند اجرا می‌کند، هر
دو سرویس را در دو پنجره‌ی جدا بالا می‌آورد و مرورگر را روی
`http://localhost:5273` باز می‌کند. برای متوقف کردن دمو، همین دو پنجره را
ببندید.

### روش دستی

```powershell
cd 26-SAP-D-MSR\backend
npm install
npm run dev
```

در یک ترمینال جدا:

```powershell
cd 26-SAP-D-MSR\frontend
npm install
npm run dev
```

فرانت‌اند روی پورت **5273** بالا می‌آید (نه ۵۱۷۳ پیش‌فرض پروژه‌ی اصلی — تا بشود
همزمان با نسخه‌ی واقعی روی همین کامپیوتر اجرایش کرد) و بک‌اند روی پورت **4100**
(نه ۴۰۰۰). آدرس `http://localhost:5273` را در مرورگر باز کنید.

**ورود:**

| نام کاربری | رمز عبور | نقش |
|---|---|---|
| `demo` | `demo1234` | مدیرعامل (دمو) |
| `guest` | `demo1234` | بازدیدکننده (دمو) |

این مقادیر در `26-SAP-D-MSR/backend/.env` تنظیم شده‌اند (کاملاً مستقل از کاربران نسخه‌ی
اصلی) و به دلخواه قابل تغییرند — برای ساخت هش رمز جدید:

```bash
node -e "console.log(require('bcryptjs').hashSync('رمز-جدید', 10))"
```

## دیتابیس‌های ساختگی از کجا آمده‌اند؟

شش فایل SQLite داخل `fake-data/output/` (`sales.db`, `receivables.db`, `pnl.db`,
`hr.db`, `targets.db`, `inventory.db`) دقیقاً همان **اسکیمای** دیتابیس‌های واقعی
پروژه (`etl/output/*.db`) را دارند — همان نام جدول‌ها، همان نام و ترتیب ستون‌ها —
اما محتوایشان توسط اسکریپت `fake-data/generate.py` با داده‌ی تصادفی (ولی
داخلی‌سازگار: کد کالا/مشتری/بازاریاب در همه‌ی جدول‌ها یکسان، جمع‌های مالی منطقی،
بازه‌های تاریخ شمسی درست) ساخته شده‌اند. بک‌اند دمو هیچ اتصالی به دیتابیس‌های واقعی
یا فایل‌های اکسل شرکت ندارد و اصلاً موتور ETL پایتونی هم در آن غیرفعال است
(`ETL_ENABLED=false`).

### بازتولید داده‌ی ساختگی

اجرای مجدد اسکریپت، هر ۶ فایل را از نو (با seed ثابت = همیشه همان نتیجه، به‌جز
تاریخ‌ها که نسبت به «امروز» تنظیم می‌شوند) بازمی‌سازد — مثلاً اگر بعد از مدتی
نوار «داده قدیمی است» در صفحه‌ی اول ظاهر شد (چون داده‌ی ساختگی ثابت است و دیگر
«تازه» به‌حساب نمی‌آید)، همین دستور کافی است:

```powershell
cd 26-SAP-D-MSR\fake-data
python generate.py
```

نیازمندی پایتونی: `pip install jdatetime` (برای تبدیل دقیق تقویم شمسی). بعد از
اجرا، فقط کافی‌ست بک‌اند دمو را ری‌استارت کنید (یا اگر در حال اجراست، خودش با چک
mtime فایل‌ها، دیتای جدید را تشخیص می‌دهد).

## Build برای استقرار تک‌پردازشی (مثل نسخه‌ی اصلی)

الگوی این بخش دقیقاً همان چیزی است که در `docs/README_DEPLOY.md` برای نسخه‌ی
اصلی توضیح داده شده: یک برنامه‌ی Node.js تنها که هم API را جواب می‌دهد و هم
فایل‌های استاتیک فرانت‌اند build‌شده را سرو می‌کند.

```powershell
cd 26-SAP-D-MSR\frontend
npm run build          # خروجی: 26-SAP-D-MSR\frontend\dist

cd ..\backend
npm run build           # خروجی: 26-SAP-D-MSR\backend\dist
```

سپس در `26-SAP-D-MSR/backend/.env` مقدار زیر را اضافه/تنظیم کنید (مسیر نسبی به
`26-SAP-D-MSR/backend`):

```
PUBLIC_DIR=../frontend/dist
```

و اجرا کنید:

```powershell
node dist\index.js
```

از این پس فقط با یک پردازش (`http://localhost:4100`) هم API و هم رابط کاربری
سرو می‌شوند — نیازی به اجرای جدای Vite dev server نیست.

## نکات مهم

- **بدون ETL خودکار**: برخلاف نسخه‌ی اصلی، این نسخه هیچ پوشه‌ی `Data/` اکسلی و
  هیچ واچر خودکاری ندارد؛ داده‌ها کاملاً ایستا هستند تا زمانی که دوباره
  `generate.py` را اجرا کنید.
- **جدا از نسخه‌ی اصلی**: `26-SAP-D-MSR/backend/data/` (که شامل `comments.db` و
  `mappings.db` است) و `26-SAP-D-MSR/backend/.env` کاملاً مستقل از پوشه‌های مشابه در
  `backend/` اصلی هستند — کامنت‌ها/گروه‌بندی‌های دستی کالا که در نسخه‌ی دمو ثبت
  می‌کنید هرگز روی نسخه‌ی واقعی اثر نمی‌گذارند و برعکس.
- **پورت‌های متفاوت** (`5273`/`4100` به‌جای `5173`/`4000`) عمداً انتخاب شده‌اند
  تا بشود این دو نسخه را همزمان روی یک کامپیوتر بالا نگه داشت.
- برای تغییر دادن حجم/بازه‌ی داده‌ی ساختگی (مثلاً تعداد ردیف فروش یا تعداد ماه
  تاریخچه)، مقادیر بالای فایل `fake-data/generate.py` (مثل `N_HISTORY_MONTHS`،
  `N_CUSTOMERS`، `N_RECEIVABLE_INVOICES`) قابل تغییرند.
