# معماری نسخه دمو مدیریتی

## نمای کلان

این سامانه یک معماری سه‌لایه با مرزهای مشخص دارد:

```text
React / MUI / ECharts
        │ REST + JWT
Express API ── Authorization / Validation / Audit
        │
SQLite domain databases + runtime databases
        │
Deterministic analytics ── optional LLM narration
```

فرانت‌اند مسئول نمایش و تعامل است، API مالک احراز هویت و قواعد کسب‌وکار است و
SQLite منبع داده دمو را نگه می‌دارد. مرورگر هیچ‌گاه مستقیماً به دیتابیس یا کلید
مدل زبانی دسترسی ندارد.

## Moduleها و Interfaceهای اصلی

### رجیستری ماژول و کاستومایز هر شرکت

`frontend/src/app/moduleManifest.ts` قرارداد مستقل از React را نگه می‌دارد و
`moduleRegistry.tsx` آن را به page و icon متصل می‌کند. `App.tsx` و Sidebar هر دو
از همین منبع ساخته می‌شوند؛ بنابراین route پنهان و منوی ناسازگار ایجاد نمی‌شود.
متغیر build-time به نام `VITE_ENABLED_MODULES` شناسه‌های مجاز یک استقرار را تعیین
می‌کند. هر شرکت همچنان استقرار، دامنه، داده و secret مستقل خودش را دارد.

### احراز هویت و مجوز

- `middleware/requireAuth.ts` توکن را با secret، issuer و audience بررسی می‌کند.
- `security/authorization.ts` نگاشت ثابت نقش به مجوز را تعریف می‌کند.
- مجوز در Interface سرور enforce می‌شود؛ پنهان‌کردن منوی فرانت‌اند فقط بهبود UX
  است و کنترل امنیتی محسوب نمی‌شود.

نقش‌های فعلی:

| نقش | دسترسی کلیدی |
|---|---|
| `admin` | داشبورد، دستیار، نظر، ورود/انتشار/بازگردانی داده و حسابرسی |
| `executive` | داشبورد، دستیار، نظر و مشاهده وضعیت داده |
| `viewer` | داشبورد، دستیار و مشاهده وضعیت داده |

### مدیریت داده بدون AI

این Module عمداً از دستیار هوشمند جداست:

1. کاربر قالب استاندارد CSV را می‌گیرد.
2. CSV یا XLSX در سرور خوانده و به ساختار مشترک تبدیل می‌شود.
3. نام ستون‌های فارسی/انگلیسی و ارقام فارسی نرمال می‌شوند.
4. نوع، تاریخ، مقادیر الزامی، کلید طبیعی و تکراری‌بودن فایل کنترل می‌شود.
5. پیش‌نمایش و خطاهای سطری نمایش داده می‌شوند.
6. انتشار فقط با مجوز `data:write` و داخل transaction انجام می‌شود.
7. مقدار قبلی ردیف‌های تغییرکرده نگه‌داری می‌شود تا rollback ممکن باشد.

Adapterهای دیتاست فقط به جداول allowlist شده فروش، موجودی و مالی دسترسی دارند؛
نام جدول یا SQL از کاربر یا مدل زبانی دریافت نمی‌شود. محدودیت دمو ۵ مگابایت و
۲۰۰۰ ردیف برای هر فایل است.

### تحلیل، KPI و نمودار

`analytics/snapshot.ts` یک snapshot قابل‌اعتماد از دیتابیس‌ها می‌سازد.
`analytics/metricCatalog.ts` تعریف رسمی شاخص‌ها، واحد، aggregation و dimensionهای
مجاز را نگه می‌دارد. `analytics/presentation.ts` درخواست را به یک schema محدود و
قابل‌رندر شامل `kpi`، `chart` و `insight` تبدیل می‌کند.

این Seam دو Implementation دارد:

- **محلی و قطعی**: بدون اینترنت، KPI و نمودار بر اساس queryهای از پیش کنترل‌شده
  ساخته می‌شوند.
- **هیبریدی**: در صورت وجود Provider فعال، مدل متن مکالمه و خلاصه را غنی‌تر می‌کند؛ اعداد
  و ویجت‌ها همچنان از مسیر قطعی می‌آیند.

مدل زبانی پشت Interface مستقل `AiProvider` قرار دارد. Adapter فعلی Groq و Adapter
عمومی OpenAI-compatible هستند؛ بنابراین تغییر سرویس با Environment انجام می‌شود و
routeهای دستیار یا منطق KPI تغییر نمی‌کنند. تنظیمات و روش افزودن Adapter جدید در
`docs/AI_PROVIDERS.md` مستند شده است.

فرانت‌اند schema را با کامپوننت‌های از پیش تعریف‌شده رندر می‌کند. پاسخ AI اجازه
تزریق JSX، HTML، JavaScript، SQL یا تنظیمات خام ECharts را ندارد.

`AnalyticsPresentation.explainability` برای هر metric شناسه رسمی، تعریف، فرمول،
جدول منبع و زمان snapshot را حمل می‌کند. عددها توسط موتور قطعی تولید می‌شوند و
Provider فقط حق تولید روایت متنی دارد.

### سلامت داده، سناریو و خروجی

- `analytics/dataHealth.ts` امتیاز قابل تست چهار بعد کیفیت را محاسبه و
  `dataHealthSource.ts` فقط پروفایل امن جداول allowlist‌شده را جمع می‌کند.
- تازگی منبع روزانه از آخرین تاریخ کسب‌وکار، منبع ماهانه از پایان آخرین دوره و
  منبع بدون ستون تاریخ از mtime فایل محاسبه می‌شود؛ چرخه انتظار هر منبع صریح است.
- `analytics/scenario.ts` یک تابع pure با guardrail ورودی است. هیچ اتصال write یا
  SQL پویا ندارد و خروجی‌های proxy و فرض‌های محاسبه را برمی‌گرداند.
- `reports/executiveReport.ts` همان snapshot قطعی و گزارش سلامت را به Excel و HTML
  چاپ‌پذیر تبدیل می‌کند؛ HTML ورودی برند را escape می‌کند و اسکریپت اجرایی ندارد.

### حسابرسی و بازیابی

ورود موفق، اعتبارسنجی فایل، انتشار و بازگردانی در دیتابیس runtime ثبت می‌شوند.
انتشارهای یک دیتاست باید به‌ترتیب معکوس بازگردانی شوند تا زنجیره تغییرات مخدوش
نشود. عملیات داده با hash فایل در برابر انتشار تصادفی دوباره محافظت می‌شود.

## امنیت اعمال‌شده

- JWT امضاشده با انقضای قابل تنظیم، issuer و audience
- RBAC و permission check روی endpointهای حساس
- CORS allowlist، حذف `X-Powered-By` و هدرهای CSP/nosniff/frame/referrer
- rate limit عمومی و محدودیت جداگانه دستیار
- سقف بدنه JSON، سقف فایل و تعداد ردیف، کنترل پسوند و parser امن Excel
- queryهای پارامتری و allowlist مقصدهای دیتابیس
- کوتاه‌سازی و علامت‌گذاری کامنت کاربر به‌عنوان داده غیرقابل‌اعتماد در prompt
- پیام خطای عمومی برای جلوگیری از افشای جزئیات داخلی

## Performance و UI/UX

- صفحات گزارش با `React.lazy` جداگانه دریافت می‌شوند.
- queryهای تحلیلی در سرور اجرا و فقط داده لازم منتقل می‌شود.
- طراحی RTL، responsive grid، loading/error/empty state و کنترل‌های keyboard در
  مسیرهای اصلی وجود دارد.
- خلاصه اجرایی بعد از ورود فقط یک‌بار باز می‌شود و هنگام بسته‌شدن کاملاً unmount
  می‌شود تا لایه نامرئی تعامل صفحه را مسدود نکند.

## مرز دمو و الزامات Production

این نسخه برای ارائه و پایلوت کنترل‌شده مناسب است، اما برای production باید این
موارد انجام شوند:

- اتصال SSO/OIDC سازمان و حذف کاربران ثابت محیطی
- انتقال runtime database و داده کسب‌وکار به PostgreSQL/SQL Server با backup و
  migration رسمی
- object storage و malware scanning برای فایل‌های ورودی بزرگ
- صف job برای import حجیم، approval دو مرحله‌ای و idempotency سازمانی
- مدیریت secret در vault، TLS اجباری، rotation کلید و SIEM مرکزی
- data classification، masking/row-level security و قرارداد نگهداری داده
- تست بار، SAST/DAST، dependency scanning در CI و تست بازیابی backup

در حالت AI روشن، داده snapshot و متن درخواست به ارائه‌دهنده مدل ارسال می‌شود؛ پیش
از استفاده با داده واقعی باید قرارداد پردازش داده و سیاست محرمانگی سازمان تأیید
شود. با `AI_ENABLED=false` این انتقال کاملاً غیرفعال است.
